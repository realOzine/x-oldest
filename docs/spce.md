# X 历史阅读 Chrome 插件 — Spec v0.1

状态：开发基线，可直接用于拆分实现任务。  
日期：2026-10-08。  
暂用功能名：历史 / Oldest。名称不构成品牌决定。

## 1. 产品目标

实现一个 Chrome 插件，让用户在 X 用户主页中，从最早可获取的帖子开始，按发布时间从旧到新连续阅读该用户的历史发帖，同时保持 X 的页面布局、视觉风格、导航和原帖交互体验。

产品承诺是「最早可获取」，具体指：在当前数据源、当前访问身份、当前筛选条件和已查询时间范围内，插件目前发现的最早帖子。该位置可能因重试或数据源变化而更新。

插件不将「没有搜索结果」解释为「没有发过帖子」，不将「分页结束」解释为「完整历史已获取」。

### 1.1 原生阅读体验的定义

| 维度 | 要求 |
| --- | --- |
| 页面位置 | 在 x.com 用户主页阅读；保留个人资料、左右栏及全站导航 |
| 视觉 | 跟随 X 的主题、文字尺度、内容宽度、边框和间距；历史状态提示保持简洁 |
| 浏览 | 使用原有页面滚动，不增加嵌套滚动容器；支持浏览器前进、后退与详情返回 |
| 卡片 | 显示作者、日期、正文、引用和媒体；链接和文本选择行为符合浏览器预期 |
| 交互 | 原帖详情、回复、点赞、转发等由 X 原生界面完成；插件提供清晰入口 |
| 退出 | 切回原生标签后恢复 X 的时间线与滚动位置；扩展出错不阻塞 X |

首版使用独立卡片渲染器实现视觉和阅读行为一致，不依赖 X 私有 React 组件。不提供看起来可以操作、实际上无效的点赞或转发按钮。如果要求在历史卡片内直接使用所有原生互动控件，应另立版本目标并先验证技术可行性。

## 2. 使用范围与非目标

### 2.1 首版支持

- 桌面 Chrome、Manifest V3、x.com 用户主页。
- 用户已有有效 X 登录状态；无需输入 API Key、Cookie 或 Token。
- 当前数据源可访问的公开账号。
- 原创帖子、引用帖；可切换包含作者发出的回复。
- 从旧到新阅读、继续加载、暂停、重试、指定起始日期、恢复阅读位置。
- 文本、图片、可获取的视频和 GIF；内容缺失时显示可理解的占位与原帖入口。
- 本地缓存、历史查询进度、每账号阅读位置。
- 中文和英文界面；日期按浏览器语言与时区展示。

### 2.2 首版不提供

- 任意账号全部历史、已删除内容恢复、绕过访问限制。
- 受保护账号、订阅限定内容的历史采集。
- 普通转帖的历史遍历；作者回复帖之外的全部评论采集。
- 跨设备同步、用户系统、云端数据库、AI 总结、全文搜索、批量媒体下载。
- 在插件中直接写入点赞、回复、转发、收藏等操作。
- Internet Archive、第三方托管服务、官方付费 API 的生产接入。
- 关闭全部 X 页面后持续采集。
- 移动端及其他浏览器支持承诺。

注册时间只作为查询起点参考，不作为首次发帖时间。页面帖数不用于计算完整度百分比。

## 3. 核心用户流程

1. 用户打开一个 X 用户主页。
2. 插件在原生标签附近增加「历史」入口；不改写 Posts、Replies、Media 等原生标签。
3. 用户点击「历史」，插件挂载独立阅读区域，记录进入前的原生滚动位置。
4. 如已有缓存，立即显示可用内容和此前阅读位置；同时标明数据查询状态。
5. 如无缓存，解析目标账号并从注册时间附近向后查询。界面显示「正在查找早期帖子」。
6. 找到第一批可展示帖子后，按时间升序呈现，说明「目前找到的最早帖子：日期」。
7. 用户向下滚动时，插件加载下一个时间窗口，并适量预取后续窗口。
8. 点击帖子详情入口，在同标签页进入 X 原生详情；返回后恢复历史模式和阅读锚点。
9. 点击原生标签或退出按钮，恢复原生时间线；暂停此页面的历史预取。

若早期窗口尚未查明，允许显示已找到的内容，但必须提示「更早的部分时间段尚未查明」。不能把这种结果称为已确认的最早位置。

## 4. 功能需求

| ID | 需求 | 验收行为 |
| --- | --- | --- |
| FR-01 | 主页入口 | 仅在识别出用户主页后显示；同一页面最多一个入口 |
| FR-02 | 稳定账号身份 | 使用 user_id 识别账号；改名后不误用其他账号缓存 |
| FR-03 | 历史起点 | 从早期范围查询；展示目前找到的最早位置和查询状态 |
| FR-04 | 升序阅读 | 在同一阅读会话和筛选条件下，已提交列表按 created_at 升序，时间相同按安全的 ID 顺序稳定排列 |
| FR-05 | 连续加载 | 列表底部接近视口时加载后续窗口；同一帖子不重复出现 |
| FR-06 | 筛选 | 默认原创与引用，可开启「包含回复」；变更筛选后查询进度独立计算 |
| FR-07 | 指定起点 | 用户可从某日期开始阅读；明确标记此前范围尚未查询 |
| FR-08 | 暂停与取消 | 暂停后不启动新请求；切换目标、筛选或路由时取消或忽略过期响应 |
| FR-09 | 中断恢复 | 每个成功批次保存数据与检查点，刷新后无需从头重抓 |
| FR-10 | 阅读位置 | 以帖子 ID 与视口内偏移保存，详情返回、刷新后恢复 |
| FR-11 | 原帖入口 | 作者、日期、正文链接、详情入口可正常打开，支持新标签页 |
| FR-12 | 内容回退 | 无正文、长文不完整、引用或媒体不可用时给出占位和原帖入口 |
| FR-13 | 查询状态 | 展示等待、查询中、已加载、未找到结果、尚未查明及受限状态 |
| FR-14 | 缓存管理 | 可清除此账号缓存和阅读位置；明确删除范围，不影响 X 账号数据 |
| FR-15 | 退出恢复 | 退出模式恢复原生标签、可见区域和滚动位置，不留下遮挡层 |

### 4.1 卡片与阅读交互

- 卡片包括头像、显示名、用户名、发布时间、正文和可获得的附件。
- 引用帖采用独立引用区域；无法获取时显示「引用内容暂不可用」。
- 回复标识必须与原创区分；不能将被回复人的内容归属到目标账号。
- 正文按数据源提供的完整文本字段选择，不能默认用截断字段替代长帖。
- 帖子正文安全渲染，不执行其中的 HTML 或 JavaScript。
- 文本选择不触发整卡跳转；链接、媒体操作与详情入口分别处理。
- 视频默认不自动播放。首版不承诺跨页面恢复视频播放进度。
- 互动数字如显示，应视为采集时快照；首版可省略，避免制造实时准确的印象。
- 图片预留尺寸；图片加载、长文展开后修正虚拟列表高度并保持当前阅读锚点。
- 帖子 ID 缺失或作者身份不能确认的搜索对象不进入主阅读列表。

## 5. 历史覆盖与用户文案

### 5.1 查询状态的语义

| 状态 | 内部含义 | 用户文案示例 |
| --- | --- | --- |
| 未查询 | 时间区间尚未执行 | 该时间段尚未查询 |
| 查询中 | 正在执行请求或分页 | 正在加载 2012 年 3 月 |
| 已结束，有结果 | 该数据源已结束本次分页并返回帖子 | 已加载 2012 年 3 月可获取的帖子 |
| 已结束，无结果 | 请求成功且本次查询没有返回帖子 | 该时间段未找到可获取的帖子 |
| 尚未查明 | 网络、解析、预算或分页异常导致未结束 | 该时间段尚未查明，可重试 |
| 访问受限 | 当前身份或数据源无法访问 | 当前无法获取该账号的历史帖子 |

「已结束」只表示本次数据源遍历结束，不表示真实历史完整。

### 5.2 显示规则

- 起点文案统一为「目前找到的最早帖子」，不使用「第一条帖子」。
- 结束文案为「已读到本次查询范围的末尾」，显示本次截止日期。
- 跨越尚未查明区间必须插入日期缺口提示，不能悄悄略过。
- 不显示无法证实的「已完成 100%」「已获取全部帖子」。
- 账号页面显示零帖或帖子计数与采集数量不同，不作为历史完整或缺失比例的证据。
- 每个会话记录查询截止时刻 T0；新发帖不插入当前历史列表。用户主动刷新后开启新查询范围。

## 6. 数据获取方案

### 6.1 首版决策

首版在 x.com 页面中复用当前登录态，通过受限页面桥接执行只读历史搜索，采用时间窗口与分页组合遍历。普通用户时间线可用于获取账号资料和近期补充，但不能作为全历史入口。

不采集、持久化或上传用户的认证 Cookie、Token。浏览器可在正常同源请求中发送当前会话凭证；如接口需要可用的请求头，只在请求执行边界处理。页面桥接不将认证信息传回扩展持久存储。

「复用登录态」是待验证的接入方案，不是默认已成立的能力。operation ID、功能参数、请求校验与返回结构可能变化，必须封装在数据源适配器中。

### 6.2 数据源能力声明

适配器必须声明：支持的帖子类型、时间边界精度、排序方向、分页方式、访问范围、已知深度限制、身份相关性及适配器版本。

搜索使用时间排序模式，不使用热门或相关性模式作为历史顺序。若当前适配器无法提供可验证的时间范围或可靠分页，显示数据源不可用，不制造完整的连续阅读结果。

数据源接口应提供 resolveUser、searchWindow、可选 readRecentTimeline、必要的 fetchPostDetail；界面与调度器不依赖内部 GraphQL 的具体结构。

### 6.3 首帖定位与窗口调度

1. 解析稳定 user_id、当前用户名及注册时间；注册时间不可获得时从 X 可用历史起点探测，并明确提示范围。
2. 从查询起点按年或较大的区间顺序探测，直到发现早期内容；不对「某一年是否有帖子」直接做二分。
3. 命中区间后按月、周、日或适配器支持的更细粒度拆分，以降低首批等待时间。
4. 对选定窗口进行分页。窗口按真实 UTC 边界组织；适配器负责映射实际查询参数并验证包含关系。
5. 当前窗口获取结束后排序、去重、提交列表；后台按顺序预取后续窗口。
6. 请求预算不足时保存进度并暂停，用户可以继续查找或选择开始日期。

不能仅因某一页少于页容量就认定窗口结束。结束依据是适配器确认的分页结束信号；重复 Cursor、连续无新增结果或不支持的响应结构归为尚未查明。

内部逻辑使用半开区间 [start, end)。如数据源边界语义不明确，采用已验证的少量重叠查询并按帖子 ID 去重。当天高频发帖不能因窗口已缩小到一天就截断，仍需分页或更细粒度切片。

窗口拆分依据分页耗时、返回量和请求预算，而不是固定「500 条」阈值。首版可先采用已验证的月窗口策略；自适应调度是性能优化，不得改变状态语义。

### 6.4 升序提交与缺口

- 不能将每页独立反转后直接追加；接口后续页可能包含更早帖子。
- 每个展示窗口先完成可获取范围的遍历，再将该窗口按时间升序提交。
- 初始窗口太大时优先拆小；原窗口结果可以缓存，但不能误标子窗口已结束。
- 正常连续阅读按时间窗口依次推进。
- 若前面的窗口失败，默认停在缺口处，提供「重试」与「跳过此时间段」。用户选择跳过后，保留明确缺口标记。
- 已显示的缓存窗口后来查明存在更早内容时，不立即重排当前视口；提示「发现更早的帖子」，用户主动进入更早位置。
- 同窗口补回遗漏帖时保留锚点并提示可刷新；严格升序承诺针对已提交的阅读视图，更新通过显式刷新重新提交。

### 6.5 请求预算与错误分类

初始调度参数为可调整的保守默认值，不视为 X 官方安全额度：

- 每个登录身份至多一个主动历史采集任务；多标签页共用调度锁。
- 只读请求默认串行，最小间隔 2 秒；根据实际响应进一步降低速率。
- 首次定位最多发起 20 个请求或执行 60 秒，先达到者暂停并保存进度；用户明确继续后增加预算。
- 自动预取最多领先 2 个展示窗口且最多新增 10 个请求，按较小预算停止。
- 网络失败最多自动重试 2 次，采用有上限的退避与抖动。
- 429 按有效的 Retry-After 或 reset 信息等待；缺少信息时至少暂停 60 秒，由后续结果决定是否继续。
- 401、账号检查、验证码、访问限制不自动循环重试，提示用户先在 X 正常界面处理。
- HTTP 200 中的业务错误、字段缺失和解析失败不能当作空结果。
- 隐藏标签页停止预取；路由离开或账号切换立即停止新请求。

取消只保证不启动新请求、过期响应不修改当前视图；已经发送到服务器的请求不能保证撤回。

## 7. 扩展架构

| 模块 | 职责 | 禁止承担的职责 |
| --- | --- | --- |
| 页面桥接，MAIN world | 同源只读请求、窄范围请求观察、临时请求上下文 | 持久存储认证信息、执行任意 URL 或任意命令 |
| Content script，ISOLATED world | 识别主页、挂载入口与阅读区域、路由与主题适配 | 将宿主 origin 的 IndexedDB 当作扩展数据库 |
| 调度器与 Service Worker | 任务队列、预算、跨标签页协调、检查点、数据查询 | 假设内存状态永远存在，依赖常驻后台循环 |
| 扩展 IndexedDB | 账号、帖子、窗口状态、阅读位置和任务记录 | 保存认证 Cookie、Token、全部浏览历史 |
| 独立 UI root | 历史卡片、窗口加载、虚拟化、阅读锚点 | 移动 X 管理的帖子节点、调用 X 私有 React 组件 |
| 数据源适配器 | 参数生成、响应解析、分页与能力声明 | 将不认识的结构当作「没有结果」 |

入口挂载在原生 React 管理区域之外的稳定容器，历史阅读区域采用独立 root。启用时通过可撤销的样式隐藏对应原生时间线，不删除或移动其帖子节点；若找不到可靠挂载位置，保持 X 可用并报告兼容问题。

Shadow DOM 可用于样式隔离，但需要显式同步主题、字体与尺寸。是否使用 Shadow DOM 由页面集成验证决定，不作为原生体验成立的依据。

技术基线为 TypeScript、Manifest V3、IndexedDB 与支持动态高度的虚拟列表。UI 框架、数据库包装库和构建工具按实现阶段选定，不构成产品依赖承诺。

## 8. 数据模型与一致性

| 实体 | 必需字段 |
| --- | --- |
| User | user_id、当前 username、username 历史、显示资料、joined_at、更新时间 |
| Post | 字符串 post_id、author_id、created_at、完整文本或可用文本、类型、reply_to_id、quoted_id、conversation_id、媒体、编辑版本关系 |
| Observation | post_id、source、observed_at、文本完整度、可见性上下文、可选经过裁剪的原始帖子对象 |
| Segment | user_id、source、filter_hash、visibility_context、adapter_version、start、end、state、cursor、截止时刻、请求统计、错误与最后查询时间 |
| ReadingPosition | user_id、filter_hash、锚点 post_id、锚点偏移、查询起点、更新时间 |
| Job | job_id、target_user_id、会话 generation、状态、预算、目标范围、拥有任务的页面、租约与检查点 |

### 8.1 存储规则

- ID 使用字符串持久化；比较时使用安全数值比较或等效逻辑，不能转换成普通 Number 后排序。
- 帖子主身份为 post_id；作者使用 user_id，不能仅以用户名关联。
- 查询进度包括筛选条件、数据源版本和访问上下文。改变这些条件不能直接复用原「已结束」结论。
- 正文、编辑关系、媒体和互动数据分别保留来源与采集时间；不能用不完整响应覆盖已知完整正文。
- 原始数据仅保留帖子解析需要的部分，不保存完整请求头或无关账号数据。
- 公共内容可复用；登录账号切换后取消任务并重建访问上下文，访问失败结论不跨账号复用。
- 写入帖子和更新该批次检查点在同一 IndexedDB 事务中完成；失败则一并回滚。
- IndexedDB 建立 user_id、created_at 和稳定 ID 排序所需索引，使用游标或等效键范围分页，不使用 OFFSET 扫描大列表。
- 扩展卸载可能删除本地数据；清理界面说明缓存用途，不将其作为永久归档承诺。
- 首版缓存只保存正文、元数据与媒体 URL，不自动保存视频文件。

### 8.2 查询状态失效

- Cursor 只能用于原查询参数和支持的适配器版本；失效后从受限重叠区间恢复，不全量清空缓存。
- 适配器重大更新可将相关 Segment 标为需要重新检查，但保留已采集内容。
- 「未找到结果」可由用户主动重查，不能无限期当作没有历史的证据。
- 自动刷新只更新当前读取需要的内容，不主动全库逐帖检查删除或可见性变化。
- 帖子后来不可用时，已保存内容须标明本地采集时间；用户刷新查明不可用后显示相应状态，不伪装成当前仍可访问。

## 9. 路由、生命周期与恢复

- 主页挂载必须幂等；同一目标不重复创建 root 或监听器。
- 切换账号、目标或筛选条件时递增 generation；旧请求返回后校验 generation 和目标 user_id。
- 进入详情前同步保存阅读锚点；历史模式作为独立导航状态记录，不能覆盖 X 使用的 history.state 字段。
- 持久记录上次阅读位置；页面内导航状态只负责当前详情往返。刷新主页可通过再次进入历史模式恢复。
- X SPA 返回同一主页时恢复历史模式；浏览器前进、后退不能造成循环导航。
- Service Worker 重启后读取 Job 与检查点；不从全局变量恢复任务。
- 页面关闭后任务状态设为等待页面；重新打开有效页面并进入历史模式时继续。
- 多标签页以租约协调同一采集任务；拥有者关闭或异常后可转移，过期响应不能重复提交。
- DOM 观察器仅监测必要容器，采用合并处理；不能对整页频繁扫描所有节点。
- UI、数据库、桥接失败均应提供退出历史模式的方式；没有稳定集成位置时不遮挡原生页面。

## 10. 隐私、权限与维护边界

- 默认本地处理；无开发者服务器、遥测或第三方转发。
- 仅申请 x.com 功能需要的 host 权限，以及经实现确认必需的扩展 API 权限。
- 首版不申请 cookies、debugger、全站访问或无限存储权限；确有需求时另行说明与评估。
- 页面消息只接受已定义的只读操作和参数白名单；检查类型、范围、请求关联与数据大小。
- 页面是可观察和干扰 MAIN 脚本的环境；不能依赖页面内随机标记作为完整安全隔离。
- 由扩展调度器决定目标和预算，页面消息不能任意启动网络请求、读取数据库或调用扩展 API。
- 日志不包含认证信息、完整请求头；诊断默认只保存错误类型、数据源版本和请求计数。
- 本地日常读取日志以环形缓冲保存，首版上限 200 条；不自动上传。
- 不执行远程下载的脚本、解析器代码或数据中的指令。适配器逻辑随扩展版本发布。
- 故障说明区分接口不兼容、未登录、限流、网络故障与不可访问，不把它们统一显示为「没有帖子」。

## 11. 性能与体验目标

以下为受控环境下的实现目标，不是对 X 网络响应或历史覆盖的保证。基准使用桌面 Chrome、1280 × 800 视口、10,000 条本地混合文本与媒体元数据；测试报告记录硬件和浏览器版本。

| 项目 | 目标 |
| --- | --- |
| 缓存首屏 | 点击历史后，缓存内容在 500 ms 内可交互展示 |
| 无缓存反馈 | 300 ms 内显示查询状态；不能空白等待 |
| 加载反馈 | 请求结束、暂停或失败后 500 ms 内更新状态 |
| 挂载数量 | 全页仅一个历史入口、一个阅读 root |
| DOM 规模 | 虚拟列表同时挂载帖子卡片不超过 100 张 |
| 阅读位置 | 详情返回后，锚点在资源尺寸稳定时与原位置偏差不超过 32 CSS px |
| 缓存预算 | 默认元数据缓存预算 200 MiB；达到预算时停止自动新增，提示清理或调整，不静默丢弃当前内容 |
| 网络使用 | 点击历史之前不主动采集历史；隐藏或退出后停止预取 |
| 大列表滚动 | 受控测试中可见卡片正常渲染，无重复项、无因分页引起的视口重置 |

远端首帖发现时间只记录实际指标，不设「必定数秒找到」的产品承诺。若定位预算用尽，立即提供继续查找和指定日期两个选项。

## 12. 异常与边界行为

| 场景 | 必须行为 |
| --- | --- |
| 未登录或会话失效 | 提示在 X 原生页面登录，暂停采集；保留可读的公开缓存 |
| 受保护账号 | 首版显示不支持历史获取；不尝试访问受限帖子 |
| 账号不存在、封禁或地区不可用 | 区分适配器能够辨识的原因；不能辨识时显示当前不可访问 |
| 整年没有搜索结果 | 标记本次未找到结果，继续后续范围；支持重查 |
| 日期窗口失败 | 停在缺口处，可重试或显式跳过 |
| 同日超过单页容量 | 持续分页或拆分；不能截断后标记已结束 |
| 重复 Cursor 或重复页面 | 有上限地检测后标记分页异常，保存数据与检查点 |
| 改名或用户名被重新使用 | 重新解析 user_id，阻止不同账号缓存混合 |
| 引用帖被删或作者不可访问 | 保留引用占位，不阻塞作者自身帖子阅读 |
| 长文或文章无法完整解析 | 标记可用部分并提供原帖入口，不显示为完整全文 |
| 媒体失效 | 显示占位，允许重试；不反复自动请求失败资源 |
| 编辑版本重复出现 | 归入编辑关系，不因新 ID 把同一逻辑帖子随意排到多年后 |
| 置顶、推荐、广告或他人帖子混入 | 依据对象类型、作者身份与查询范围过滤 |
| 中断、标签关闭或后台停止 | 已提交批次可恢复；下一批次重试时幂等去重 |
| 两标签页同时进入同一账号 | 共用任务预算，一处采集、两处按需读取 |
| 新数据改变最早位置 | 提示发现更早帖子，保留当前阅读位置 |
| X 页面结构变化 | 挂载失败时不影响原生页面；入口说明兼容问题 |
| 数据库容量或事务失败 | 停止采集并提示，不能继续推进检查点 |

## 13. 验收与测试矩阵

### 13.1 可重复的功能验收

使用固定响应样本覆盖分页、短页、重复页、错误与边界，不以线上搜索结果作为排序和恢复正确性的唯一依据。

| ID | 测试 | 通过标准 |
| --- | --- | --- |
| AC-01 | 启用与退出 | 入口无重复，原生标签和导航可用，退出恢复原位置 |
| AC-02 | 反向分页 | 多页由新到旧返回，提交后整体从旧到新且无重复 |
| AC-03 | 时间边界 | 月末、午夜、同秒及重叠查询样本无丢失、无重复 |
| AC-04 | 空结果与错误 | 成功空结果、HTTP 200 业务错误、解析失败分别归类 |
| AC-05 | 缺口 | 中间窗口失败时停止；显式跳过后可继续且保留提示 |
| AC-06 | 首帖语义 | 更早范围有失败或未查询时不声称已确认第一条 |
| AC-07 | 筛选隔离 | 包含回复切换不复用错误的窗口结束状态 |
| AC-08 | 路由竞态 | 从用户 A 切到 B 后，A 的延迟响应不进入 B 的列表 |
| AC-09 | 检查点事务 | 批次写入失败不推进游标；重启恢复不漏帖、不重复 |
| AC-10 | 详情返回 | 同标签详情往返、前进与后退恢复历史模式与锚点 |
| AC-11 | 身份变化 | 改名保留同一账号数据；用户名重新使用时不混库 |
| AC-12 | 媒体与排版 | 明暗主题、长文、引用、图片加载、窄视口不破坏滚动与文本选择 |
| AC-13 | 限流与取消 | 429 停止请求并等待；暂停、隐藏和退出停止新预取 |
| AC-14 | 多页面协调 | 两标签共用一个采集任务，拥有者退出后可恢复 |
| AC-15 | 桥接边界 | 非白名单操作、超大消息、无关联响应不能触发扩展特权行为 |
| AC-16 | 本地缓存 | 刷新后可恢复缓存和位置；清理只删除用户选定范围 |
| AC-17 | 性能 | 达到第 11 节的受控环境指标，记录实际结果 |

### 13.2 线上接入验证

至少选择 5 个公开账号，包括长期低频、长期高频、间歇停更、大量回复和新账号；记录当日可用性和数据源版本。

为每个账号准备若干当前仍可打开的早期帖子作为样本，检查插件能否在相应窗口发现它们。用原生搜索对照异常区间，记录稳定性与遗漏，不将对照结果或主页帖数当作完整历史真值。

在实际 X 页面验证明暗主题、800/1280/1920 CSS px 宽度，以及 100%/125%/150% 缩放下的入口、详情返回和退出恢复。

## 14. 开发阶段与完成门槛

### M0 — 数据可行性验证

完成稳定账号解析、一个指定早期窗口的只读查询、连续分页、错误分类、时间边界验证与样本报告。此阶段可以使用简单列表，不需要完整卡片。

门槛：在测试账号的指定窗口能获取已知仍可见样本并正确分页；若内部接口方案不可行，记录原因并调整数据源方案。不能把「仅能获取近期内容」默认为满足首版目标。

### M1 — 原生页面集成

完成历史入口、独立 root、基础卡片、主题同步、详情跳转、路由管理和退出恢复。

门槛：AC-01、AC-08、AC-10、AC-12 通过；原生页面正常功能不受影响。

### M2 — 连续历史阅读

完成起点探测、窗口调度、整体升序提交、回复筛选、显式缺口处理、加载与暂停。

门槛：AC-02 至 AC-07、AC-13 通过；用户可从已找到早期帖子连续读到后续窗口。

### M3 — 缓存与恢复

完成扩展 IndexedDB、检查点事务、阅读锚点、多标签调度、容量处理。

门槛：AC-09、AC-11、AC-14、AC-16 通过；刷新、后台重启和页面关闭不损坏已保存进度。

### M4 — 发布准备

完成性能验证、桥接审查、日志脱敏、权限与隐私说明、安装包验证、线上样本验证。

门槛：全体验收通过，已知限制有明确说明，扩展仅使用声明过的权限，无认证信息持久化或上传。

不按未经验证的固定工期承诺交付；M0 完成后再估算后续工作量。

## 15. 首版完成定义

用户可以在一个支持的公开账号主页进入历史模式，从目前发现的最早可获取帖子开始，按时间升序连续阅读；在明确的缺口和限流状态下暂停、重试或选择继续；访问原帖详情后返回原位置；退出后恢复 X 原生页面。

首版同时满足：没有完整历史的误导承诺、没有无响应的仿原生互动按钮、没有认证信息持久化或上传、没有因插件失败破坏 X 页面。

## 16. 后续扩展方向

- 可选官方全档案 API：需独立预算、凭证与费用说明。
- 可选第三方服务：需明确数据接收方、覆盖能力与配额。
- 本人或作者提供的 Archive 导入：独立的本地数据来源与快照说明。
- Internet Archive 补充：保留来源与快照时间，不与当前状态混淆。
- 普通转帖：先验证是否能获得用户转发时间，再定义事件时间线模型。
- 线程阅读：提供明确的线程分组视图，不改变时间顺序视图的含义。
- 直接互动：另行定义写权限、请求适配、状态同步与失败回退。

## 17. 技术依据

以下资料用于说明设计约束，不替代 M0 的实际接入验证；本规格不依赖某个开源工具对完整历史的宣传。

- [X 用户时间线文档](https://docs.x.com/x-api/posts/timelines/introduction)：普通用户时间线历史深度有限。
- [X 搜索文档](https://docs.x.com/x-api/posts/search/introduction)：近期与全档案搜索分别提供不同历史范围。
- [X 旧帖缺失说明](https://help.x.com/en/using-x/missing-posts)：搜索和时间线可能未显示旧内容。
- [Chrome 扩展存储与 Cookie](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)：content script 与扩展 origin 存储归属不同。
- [Chrome 扩展 Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)：任务需容忍停止与重启。
- [Chrome Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)：执行环境、桥接与内容安全约束。
- [Manifest V3 发布要求](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements)：适配器更新须遵守远程代码限制。
